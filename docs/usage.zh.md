# 使用 modelspoke

[English](usage.md) · [README](../README.md) · [README.zh](../README.zh.md) · [design.md](design.md) · [llama-swap 设置](llama-swap-setup.zh.md)

README 里的安装步骤能让你拿到一个可用的提供方；这篇文档讲安装之后怎么
用 — 模型的配置项如何解析、UI 里每个字段的作用、以及手工编辑配置文件
时它的完整形状。

## 解析链条

每个模型的每个能力字段 — 上下文窗口、最大输出 tokens、图像输入、思考
级别 — 都独立地按"从最具体到最宽泛"的来源顺序解析：

1. **你的配置** — 你在模型详情里设置的值，或 `overrides:` 块里的条目。
2. **服务器发现** — 从端点的 `GET /v1/models` 实时读取的值（llama-swap
   来自 `llama-swap.yaml` 的 `metadata` 块；Ollama 来自它的 API 扩展）。
   每次展开提供方或模型时都会重新拉取，所以 UI 始终反映服务器的
   当前状态。
3. **内置预设** — 你的模型 id 匹配其 `match` 模式、且服务器没有提供该
   字段时，预设目录中匹配的条目（见
   [preset-authoring.zh.md](preset-authoring.zh.md)）。
4. **内置默认值** — 保守的兜底（无思考维度、纯文本输入、不声明上限）。

逐字段取第一个非空值。两个实际后果：

- **清空一个字段是"释放"，不是"删除"。** 清空详情里你填过的值，该字段
  就会落回下一层 — 例如清空你手填的上下文窗口，发现（或预设）会重新
  接管。
- **预设永远不压过你。** 你设置了某个字段，它就压过发现和预设 — 仅限
  该字段。

完整机制 — 包括每个字段的来源如何被报告 — 见
[design.md](design.md) 的 "Tiered reasoning-metadata resolution" 一节。

## 提供方卡片

每个提供方是一行（名称 + 状态点 + 编辑 / 删除），展开后就是一张原位
卡片：

- **名称** — 提供方的身份键。改名会带着它的模型和覆盖一起走。
- **Base URL** — OpenAI 兼容端点，如 `http://127.0.0.1:8080/v1`。
- **API 密钥环境变量名** — 存放密钥的*环境变量*的*名字*。modelspoke
  只从 `process.env` 读取；密钥的*值*绝不写入 `settings.yaml`。无密钥的
  本地服务器可省略 — 此时不发送认证头。
- **状态点** — 绿色：最近一次目录拉取成功。红色：拉取失败（悬停看原因）。
  灰色：尚未检查。

**模型列表就是策展。** 只有列在提供方模型列表里的模型才会被 agent
寻址。每行是 `[显示名][wire id][箭头][−]`：

- **显示名**（可编辑）是模型在 agent 中的身份 — 留空则默认等于
  wire id。
- **wire id**（下拉框）是实际走线上的模型 id；由拉取的目录填充但可
  手输，所以也能引用服务器尚未提供的模型。允许重复 wire id 作为命名
  变体。
- **箭头**展开该模型的详情（见下）。
- **−**把模型移出服务集合。

**Apply**把你在这张卡片上的所有改动 — 提供方字段、服务集合、每模型
编辑 — 作为一次原子写入提交；**Cancel**回滚到最后一次提交的状态。
只是查看、没改动的卡片不会写入任何东西。

## 模型详情

箭头展开某个模型的可编辑配置。所有没动过的字段都保持"有效值"（解析
链条的结果）作为种子，且绝不原样提交 — 只有你真正改过的字段才会写入：

- **上下文窗口** — 模型的上下文大小（tokens）。
- **最大输出 tokens** — 每次响应的输出上限。
- **图像输入** — 声明该模型接受图像。这是 agent 的 `read_image` 工具
  检查的能力门：取消勾选就关掉该模型的视觉。
- **推理强度** — 声明该模型有思考维度。**不勾选是"无思考级别"
  （nothink）哨兵**，不只是"关"（见下）。
- **思考级别映射** — 每个可选级别一行：UI 提供的级别（左）与模型实际
  接受的取值（右）。按模板接受的范围增删行。这里的错误是弄坏模型的
  主要途径：模板要么对未列出的取值 `raise`（中途 400），要么静默
  忽略（你的"强度"设置什么都不做）。
- **默认强度** — agent 不显式选择时使用的级别。模型不接受的强度会被
  拒绝，绝不静默钳制。

深层模板契约字段（`compat`：`thinkingFormat`、`chatTemplateKwargs` 的
`$var` 绑定）刻意**不在** UI 里：它们是只读的，在 `settings.yaml` 里
手工编辑，并逐字节保留通过每次 UI 写入 — 那里的一次部分写入会替换掉
模板的思考绑定，中途弄坏模型。

详情上的**重置**把该模型的配置退回更低的层；模型留在服务列表里。

## 无思考级别（nothink）模型

有些端点上的模型副本没有可选的思考级别 — 典型场景是 nothink GGUF 副本
与推理版在同一个 wire id 下并存。在详情里，**不勾选"推理强度"**
声明的正是这一点（nothink 哨兵）：该模型完全不提供思考维度，请求到它的
任何强度都被钳制为 off — 什么都不发送，因为它没有可落地的旋钮。

这与*级别映射*里带一行 `off` 的模型不同：那仍然是推理模型，只是给了它
一个"少想一点"的档位。

## 图像

当模型声明了**图像输入**，两件事变得可用（stock dsh 自定义提供方做不
到）：

- agent 的 `read_image` 工具在该模型上通过能力门，图像工具结果能走到
  线上。
- 你在输入框粘贴的图像以 `image_url` 部分走线。

在 web UI 里，`read_image` 的结果默认渲染为真实的内联图像（连同工具的
文本）；`modelspoke:` 段里的 `renderReadImages` 设置关掉它，届时该行
交回 dsh 的通用工具渲染。

**已知限制。** 目前还没有请求预算管理：在很长的线程上，
`input + max_tokens` 可能超过模型上下文，服务器返回 400（sglang 不
钳制）。把每模型的最大输出 tokens 设在上下文窗口的一半以下是目前的
对策；正式的预算 + 卸载方案已列入计划。

## 配置文件

UI 写入的一切都住在 `~/.dsh/settings.yaml` 的 `modelspoke:` 段里，你也
可以同样地手工编辑 — dsh 监视该文件，改动实时生效：

```yaml
modelspoke:
  routes:
    - name: llama-swap              # 提供方键（唯一）
      baseURL: http://127.0.0.1:8080/v1
      apiKeyEnv: LLAMA_SWAP_API_KEY # 可选 — 变量名，不是变量的值
      models:                       # 服务集合；在列 = 在服务
        - name: qwen3.8-27b         # 身份（agent 对它的称呼）
          id: qwen3.8-27b-6000pro   # wire id（走线的 id）
          defaultEffort: medium     # 可选
          contextWindow: 262144     # 任何规范字段，当你设置时
          maxTokens: 65536
          input: [text, image]
          thinkingLevelMap:         # 级别 → 模型取值 的映射
            off: low
            low: low
            medium: medium
            xhigh: xhigh
      overrides:                    # 每提供方，精确 wire id → 字段值
        qwen3.8-27b-mtp: { contextWindow: 32768 }
  overrides:                        # 遗留的顶层形状 — 仍然读取；
    some-wire-id: { maxTokens: 4096 }  # 同 id 条目在提供方上逐字段获胜
  renderReadImages: true            # read_image 内联渲染（仅 web UI）
```

没有 `models:` 列表的提供方提供其**完整目录**（按发现）；对这类提供方
的第一次编辑（删行、加模型、改字段）会用拉取的目录把列表物化出来，
然后应用该编辑。未改动的提供方逐字节原样往返。

## 什么实时生效，什么需要重启

- **内容变更** — `settings.yaml` 里的一切，包括整个 `modelspoke:` 段 —
  被监视并实时生效。
- **（反）安装包** — dsh 按进程生命周期缓存包元数据，所以在 profile 里
  添加或移除 modelspoke 之后重启一次。其他什么都不需要。
- **tui/headless profile** — 设置页和引导步骤是 web 界面；在
  tui/headless 里插件以完全相同的方式提供模型，`settings.yaml` 段（加上
  尚无任何提供方时首次启动的日志提示）就是操作界面。
